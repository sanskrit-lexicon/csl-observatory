Between January 2025 and July 2026 a volunteer team page-indexed the printed editions that the Böhtlingk-Roth *Sanskrit-Wörterbuch* (PWG) cites, so that an `<ls>` citation in the dictionary can be resolved to the page image of the edition it cites. This report measures that campaign **by citation mass** — how much of the dictionary's citation apparatus the indexed works carry — because a 159-page *Kumārasaṃbhava* and a 2,420-page *Taittirīyabrāhmaṇa* are not equal work, and neither are equal payoff.

**Nothing unresolved.** Every tracked row names a work the dictionary's own bibliography lists.

### 6.2 Citation counts — NOT commensurable, and the sheet's provenance is open

The sheet's `Citation count` column and the full-dictionary `<ls>` extraction ([`sortedcrefs.txt`](https://github.com/sanskrit-lexicon/PWG/blob/main/pwg_ls/pwg_dhaval/abbrvwork/abbrvoutput/sortedcrefs.txt)) count **different objects**, so they cannot be reconciled row by row and no attempt is made to. The extraction keys on a *cleaned citation string* — canto and śloka numbers stripped, everything else kept — so one book scatters across many keys (`MED.`, `MED. k.`, `MED. kh.`, `MED. im ŚKDR.` …). The sheet keys on a *book*.

Over the 56 rows where both numbers exist, the sheet/extraction ratio ranges from **1.2× to 433.0×** with median **2.09×** — a spread far too wide for the two to be measuring one quantity with noise.

For scale, the extraction totals **344,229** `<ls>` occurrences over 9,321 distinct cleaned strings across the whole dictionary.

> **Open question, recorded not resolved.** Which extraction produced the sheet's `Citation count` column is not documented anywhere reachable from the sheet, and it reproduces neither the bare-string counts nor a leading-abbreviation rollup of them. Until that provenance is established, the sheet's counts are used **only** as a consistent internal ranking (they order the works the same way any reasonable count would), never as a share of a dictionary-wide denominator. Resolving it needs the coordinator who built the column, not more computation.

A third count exists and is smaller by construction: the translated-article subset ([`citation_sources.json`](https://github.com/sanskrit-lexicon/PWG/blob/main/pwg_ls/pwg_ru_coverage/citation_sources.json)) resolves 67 of these abbreviations, the heaviest being `R.` 2,970, `RAGH.` 566, `RĀJA-TAR.` 543, `VARĀH. BṚH. S.` 537, `PAÑCAT.` 482. It measures ~51 translated roots, not the dictionary, and is reported in the registry for reuse-value ranking only. Where a row's own code is not in that measurement the registry records the parent abbreviation it matched, in `ru_match_key` — volume rows sharing a parent must not be summed.

Verified by a dated static audit of the resolver source and the live GitHub org — see [`scan_target_audit.tsv`](https://github.com/sanskrit-lexicon/csl-observatory/blob/main/data/pwg_scan_index_tracker/scan_target_audit.tsv). All 37 directories are real public repositories under [sanskrit-lexicon-scans](https://github.com/sanskrit-lexicon-scans), each serving a page-lookup app at `https://sanskrit-lexicon-scans.github.io/<dir>/`; together they hold about 11.2 GB of page images.

### Defects this audit found

Each is a concrete, checkable claim about a specific line of the resolver or a specific tracker cell — not a heuristic guess.

- **`amara_col`** — mis-keyed. Wired, but unreachable from the code 'AK.', which always lands on amara_dlc. amara_col needs COL., COLEBR., or 'AK. ed. COLEBR.'.
- **`pancar`** — partial. 2-parameter citations return None; only the 3-param and 'S. <page>' forms resolve.
- **`rajatar`** — yes; tracker spells it `rAjatar`, which GitHub Pages will not serve. Wired as lowercase 'rajatar'. The tracker writes 'rAjatar'; GitHub Pages paths are case-sensitive, so a viewer link built from the tracker spelling 404s. Tracker defect, not a wiring gap.
- **`rvps`** — no. HARD UNWIRED: 'rvps' appears 0 times in ls_resolver.py. The only Pratisakhya-shaped pattern routes RV. PRATIS. to the Rgveda hymn pages, so a Pratisakhya adhyaya,sutra reference MISLINKS to an unrelated RV hymn anchor; the tracker's own 'RV. PRAT.' spelling matches no pattern at all.
- **`taittiriyabr`** — partial. Resolves only at 4-parameter arity; 'TBR. 1,2,3' returns None with no fallback -- uppercase 'TBR.' is absent from the prefix map.
- **`taittiriyas`** — partial. Resolves only at 4-parameter arity; 'TS. 1,2,3' and 'TS. 1,2' return None. The 3-param helper exists but its dispatch branch is unreachable (prefix-map value never equals the tested literal).

> **The `rvps` case is a wrong link, not a missing one.** A Ṛgveda-Prātiśākhya citation does not fail to resolve — it resolves to an Ṛgveda *hymn* anchor, a different text. A silent wrong answer is worse than a visible gap, so this one is filed as an integrity defect rather than left in a backlog.

## 8 · Data-quality notes on the sheet itself

- **Book-number collisions.** `69` — the same `Book No.` is used by more than one row, so it is not a key. The registry keys on the LS code.
- **Serial-number gaps.** The sheet's own `S. No.` column skips 57, 65, 66, 67 — rows were deleted after numbering.
- **Leading-slash typo** in the scan-directory cell for `ṚV. PRĀT.`; normalized in the registry.
- **The sheet's own summary tabs are stale.** Its `Counts` tab stops at (2025) September, while the `Works` tab records work through 2026-07. Every number in this report is recomputed from `Works`; the summary tabs are snapshotted but not used.
- **`Works finished` lists works absent from `Works`** — *RAGHUVANSA*, *TRIKĀṆḌAŚEṢA 1807 Calc. ed.*, *VOPADEVA'S Grammatik : Bohtlingk*, *ŚATAPATHABRĀHMAṆA*. Either a plan that never became a tracked row, or a row deleted from `Works`; the registry follows `Works`.
- **One redaction in the committed snapshot.** The sheet's `Team` tab maps each volunteer's real personal name to their GitHub handle. The handles are public — they are on every coordinating issue — but that linkage is not, and this repository is. The name column is redacted at fetch time; the handle column, and therefore every credit and count in this report, is untouched.
- **15 rows carry no citation count** (the sheet writes `- - -` where a multi-volume work's count sits on its first volume). Their mass is therefore attributed to the parent row, and per-volume mass figures in this report are floors, not exact.
