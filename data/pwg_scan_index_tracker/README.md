# pwg_scan_index_tracker — the PWG literary-source scan-indexing campaign, as data

_Created: 27-07-2026 · Last updated: 27-07-2026_

Between January 2025 and July 2026 a volunteer team page-indexed the printed
editions cited by the Böhtlingk-Roth *Sanskrit-Wörterbuch* (PWG), so that an `<ls>`
citation in the dictionary can be resolved to a page image of the edition it cites.
The campaign was coordinated in per-source GitHub issues on
[sanskrit-lexicon/PWG](https://github.com/sanskrit-lexicon/PWG/issues) and
[sanskrit-lexicon/PWK](https://github.com/sanskrit-lexicon/PWK/issues), and tracked
in a maintainer-kept Google Sheet.

This directory is that sheet turned into committed, machine-readable data, plus the
derivations the observatory needs from it.

## Provenance

- **Upstream:** [PWG literary-sources scan-index tracker](https://docs.google.com/spreadsheets/d/1rcYfQE0D26RNdWSmRQzhFnV3Gf248wSuldTj-wt8_O0/edit?gid=0)
  (link-public, maintainer-kept). The sheet is **live and volatile** — it is the
  campaign's working document, not a release. The snapshot here is a point-in-time
  copy; re-take it with `python scripts/pwg_scan_index.py --fetch`.
- **Snapshot taken:** 27-07-2026, all four tabs.
- **The snapshot is the input of record.** Every derived file in this directory is
  regenerated from `snapshot/`, never from the network, so a checkout reproduces the
  reports offline and byte-identically.
- **One redaction, applied at fetch time.** The sheet's `Team` tab maps each volunteer's
  real personal name to their GitHub handle. The handles are public — they appear on every
  coordinating issue — but that name-to-handle linkage is not, and this repository is.
  The name column is therefore replaced with `[redacted: personal name]` by
  `REDACT_COLUMNS` in the generator, so re-running `--fetch` cannot reintroduce it. The
  handle column is untouched: every credit, count, and per-volunteer figure in the reports
  is unaffected. Publishing the names is a human decision, not an automated one.

- **`scan_target_audit.tsv` is a dated static audit, not a per-run derivation.** Built
  27-07-2026 (H1706, Opus 5 `claude-opus-5`) from two read-only passes: the live GitHub API
  over the [sanskrit-lexicon-scans](https://github.com/sanskrit-lexicon-scans) org
  (existence, default branch, size, last push, Pages status for all 37 directories), and a
  static read plus ~110 empirical probe calls against
  [`ls_resolver.py`](https://github.com/gasyoun/SanskritLexicography/blob/master/RussianTranslation/src/ls_resolver.py)
  in the RussianTranslation workspace. It is committed rather than recomputed because it
  costs live API calls and reaches into another repository. Re-verify it when the resolver
  changes.

## Registry schema

`pwg_scan_index.tsv`, tab-separated, one row per tracked literary source.

| Column | Meaning |
|---|---|
| `ls_code` | The PWG literary-source abbreviation, presentation marks stripped. The row key. |
| `ls_code_raw` | Exactly as the sheet writes it, including the ★ Vedic mark and volume suffix. |
| `ls_code_base` | Edition parentheticals removed, for joining against the bibliography. |
| `book_no`, `volume` | The sheet's physical-book bookkeeping. `book_no` is **not** unique — do not key on it. |
| `title` | Descriptive title of the edition, as the sheet gives it. |
| `status` | Normalized from the sheet's `Index Status`: `done`, `on-going`, `to-do`, `page-wise`, `nr-indirect`, `nr-alt-name`. |
| `status_gloss` | What that status means operationally. |
| `vedic_marked` | The source sheet's ★. The marked set is exactly the Vedic saṃhitā / brāhmaṇa / upaniṣad / śrauta- and gṛhya-sūtra / prātiśākhya group. |
| `shares_book_with_previous` | The sheet's `*` prefix: this work is bound in the same physical book as the row above. |
| `citation_count` | The sheet's own count. **Ranking only** — see the caveat below. |
| `total_pages` | Pages in the edition indexed. |
| `volunteer` | The `Reserved/Indexed by` cell, verbatim, `@handle` form. |
| `started`, `finished`, `index_posted`, `public_link` | ISO dates; empty where the sheet leaves them empty. |
| `issue_repo`, `issue_no`, `issue_url` | The coordinating GitHub issue. |
| `scan_dir`, `scan_url` | The scan-page directory under [sanskrit-lexicon-scans](https://github.com/sanskrit-lexicon-scans). |
| `in_pwgbib` | The abbreviation this code resolved to in the PWG bibliography. |
| `dict_citations`, `dict_citations_key` | Occurrences of the code as a bare cleaned citation string in the full-dictionary `<ls>` extraction. |
| `count_ratio` | `citation_count / dict_citations`. A ratio, not a verdict — the two count different objects. |
| `edition_qualified` | The code carries an edition parenthetical, so it cannot be matched to a bare abbreviation without ambiguity. |
| `ru_subset_refs`, `ru_subset_scan`, `ru_match_key` | Reference counts from the translated-article-subset measurement, and which spelling matched. |
| `resolver_repos` | Scan/HTML repositories the citation resolver was observed emitting for that abbreviation. |
| `scan_wired` | Whether this row's `scan_dir` appears among those observed targets. |
| `sheet_row_no` | The sheet's own `S. No.`, which has gaps. |

## Caveats that matter before you reuse this

1. **`citation_count` has unresolved provenance.** It reproduces neither the
   bare-string counts nor a leading-abbreviation rollup of the PWG `<ls>` extraction,
   and the sheet does not say where it came from. Use it to *rank* works; never divide
   it by a dictionary-wide total. Full argument:
   [`reports/pwg_scan_index.md`](https://github.com/sanskrit-lexicon/csl-observatory/blob/main/reports/pwg_scan_index.md)
   §6.2.
2. **Multi-volume works carry their count once.** The sheet puts a work's citation
   count on volume 1 and writes `- - -` on the rest, so per-volume mass is a floor and
   a volunteer who worked only on later volumes reads as zero mass.
3. **`scan_wired` is weak evidence.** It is observed over the ~51-root translated
   subset only; absence flags a wiring check, it does not prove the target is missing.
4. **Volunteer attribution is the sheet's, not GitHub's.** Names and handles are taken
   from the sheet and the public issue trail exactly as they appear there.
5. **The upstream sheet's own summary tabs are stale** (`counts.csv` stops at September
   2025 while `works.csv` runs to July 2026). They are snapshotted for completeness and
   are **not** used in any derivation.
