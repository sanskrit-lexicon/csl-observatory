# Datasheet — obst-bench v1 (frozen benchmark view over the E32 correction-event release)

_Created: 24-10-2026 · Last updated: 24-10-2026_

Describes the benchmark `obst-bench/v1/` — a frozen train/dev/test view over
the released corpus
[`observatory/site/src/data/correction_events_release.csv`](../observatory/site/src/data/correction_events_release.csv)
and its derivation. Snapshot: **2026-10-24**, pinned to the E32 release of
record (2026-10-10, SHA-256 `a27fec9e…faaf`). Regenerate with the pipeline in
*Maintenance and Reproduction* below. Filled per
[`docs/DATASHEET_TEMPLATE.md`](DATASHEET_TEMPLATE.md); the corpus datasheet is
[`docs/DATASHEET.md`](DATASHEET.md) and is not replaced by this file.

## Motivation

- **Purpose.** Turn the released E32 correction-event corpus into an *enterable
  benchmark*: a frozen test split, a documented submission format and a scorer
  a third party can run, with two reproducible reference baselines. Supports
  annotation-error detection (minimal-pair ranking) and microstructure
  location classification over correction events.
- **Created by.** M. Gasūns and the CDSL / sanskrit-lexicon community; the
  benchmark view is generated by `scripts/obst_bench.py` from the E32 release,
  itself derived from the committed correction history of `csl-orig`.
- **Funding / sponsor.** None.

## Composition

- **Instances.** One `detection` test row = one minimal pair (two surface forms
  of a single correction event); one `location` test row = one derived event
  with its edit-op features. Test: 3,127 pairs (6,254 tokens) and 9,729 rows.
- **Layers / provenance mix.** Both tasks are views over the E32 release's own
  rows: 14,670 train / 3,144 dev / 3,127 test form-layer pairs and the
  release's `train` (15,788) / `test` (9,729) derived-event rows. No row is
  invented, relabelled or re-cut by this benchmark.
- **Coverage.** The E32 temporal range (2014-03-18 → 2026-05-30), 43
  dictionaries, 208 corrector aliases. The detection test window is the most
  recent 15 % of form-layer events (the chronological tail).
- **Source edition + page range.** Not applicable — the corpus derives from
  digitized dictionaries (CDSL) with citation references, not a single printed
  edition with page ranges.
- **Fields.** `detection` rows: `pair_id`, `event_id`, `date`, `form_a`,
  `form_b` (+ `gold` in train/dev and in `scoring_only/`); `location` rows:
  `row_id`, `event_id`, `date`, `features` (+ `gold` in train and
  `scoring_only/`). Per-file digests and counts in `SPLITS.json`; the corpus
  schema is [`data/schema/correction-event.schema.json`](../data/schema/correction-event.schema.json).
- **Labels.** `detection`: which of the two forms is the erroneous
  (pre-correction) one — mechanical, read off the correction event's old/new
  side. `location`: `error_component` ∈ {sense, headword, markup, citation,
  meta, grammar} — derived by the release's attribution pipeline
  (`evidence_level=derived` only). Neither axis is human-adjudicated.
- **Sampling.** Full population under the stated filter (form layer with both
  sides single tokens; derived events with a known component) — not a sample.
- **Sensitive data.** None added. Correctors appear only as the release's
  public aliases/pseudonyms; no email addresses, no student data.

## Encoding & Transliteration Regime

- **Character encoding.** UTF-8, LF newlines in every emitted file; digests are
  computed over LF-normalised bytes so a Windows checkout and Linux CI agree.
- **Script / romanization scheme(s).** IAST (`form_a`, `form_b`, the feature
  strings); class labels are ASCII.
- **Conversion provenance.** Inherited unchanged from E32; the benchmark adds
  no transliteration step and keeps no raw source strings of its own.

## Collection Process

- **How.** Deterministic projection of the E32 CSV: filter, chronological
  split, seeded A/B presentation order, feature extraction
  (`scripts/obs_t_baselines.py::feats`).
- **Who.** Automated (`scripts/obst_bench.py`); no manual annotation.
- **Timeframe.** Benchmark frozen 2026-10-24 over the E32 cut of 2026-10-10.

## Preprocessing, Cleaning, and Labeling

- Rows are filtered exactly as the published OBS-T baselines filter them, so
  the benchmark numbers are comparable with
  [`reports/obs_t_baselines_field_metrics.md`](../reports/obs_t_baselines_field_metrics.md).
- Detection test pairs are the scorable subset (`old != new`); the 17 identity
  pairs in the chronological test window are dropped because they carry no
  label, and the 79 identity pairs in train are kept for the language model.
- A/B order is `sha256("obst-bench-v1"|event_id)` parity — deterministic, and
  independent of the gold label, so no position prior leaks the answer.
- Uncertain rows are excluded, never silently promoted: `error_component =
  unknown` is out of the location task, as in the published classifier.
- No audit sample is produced by the benchmark; it inherits the release's gold
  sample (`scripts/obs_t_gold.py`, human-gated).

## Known Gaps & Label-Quality State

- **Evaluation harness.** `scripts/obst_bench.py` — `selftest`, `score`,
  `check`; outputs land in `obst-bench/v1/baselines/*.scores.json` and the
  site summary `observatory/site/src/data/obst_bench_v1.json`.
- **Cohen's κ.** Detection κ 0.041 (gold vs B1 baseline, 6,182 non-tie
  tokens); location κ 0.473 for the published NB baseline (9,729 rows). The
  single-rater gold means κ measures baseline-vs-gold, not inter-annotator
  agreement; no human double annotation exists at this scale.
- **Per-class P/R/F1.** Committed in `obst-bench/v1/baselines/` and in the
  H6388 report above; every value carries its denominator.
- **Evidence-level split.** Location uses `evidence_level=derived` only (the
  high-confidence stratum); the `inferred` stratum is not benchmarked.
- **Known gaps.** Contamination exposure (see Uses/Caveats); α on detection is
  near chance (0.041), so the task is hard for surface baselines and any
  leaderboard should report the baseline row alongside; no human gold sample
  is large enough to compute a meaningful inter-annotator κ.

## Uses

- **Intended.** Benchmarking annotation-error detection and error-location
  classification on correction events; reproducible comparison against the two
  reference baselines; a concrete entry point for the A73 ISCLS-9 resource
  paper.
- **Caveats.** The source repositories are public git history, so the corpus is
  **contamination-exposed**: a model may have memorised the corrected lines. A
  score is not a clean generalisation estimate. Report it as "obst-bench v1,
  contamination-exposed".
- **Discouraged.** Do not treat a v1 score as evidence of real-world
  proofreading ability; do not tune on `detection/test.tsv` gold (use
  `dev.tsv`); do not compare v1 scores across an E32 re-cut (the digests move).

## Distribution

- **Where.** This repository, `obst-bench/v1/`; corpus archived at Zenodo
  (concept DOI [10.5281/zenodo.21346705](https://doi.org/10.5281/zenodo.21346705),
  version v1.14.0). The benchmark itself adds no deposit.
- **Data license.** CC BY 4.0 — [`DATA_LICENSE.md`](../DATA_LICENSE.md).
- **Code license.** GPL-3.0 — [`LICENSE`](../LICENSE).
- **Splits.** `detection`: chronological 70/15/15 over `(date, event_id)`,
  frozen by digest, gold scoring-only; `location`: the release's own
  train/test column (no dev split exists — the tuning fence is the frozen test
  digest).

## Maintenance and Reproduction

- **Maintainer.** csl-observatory repo (M. Gasūns).
- **Updates.** A new benchmark version only when E32 is re-cut; v1 stays frozen
  even if the working CSV moves (the build refuses a digest mismatch).
- **Automated pipeline.**

```bash
python scripts/obst_bench.py build      # splits + SPLITS.json from the pinned E32 CSV
python scripts/obst_bench.py baselines  # reference baselines + score JSONs + site summary
python scripts/obst_bench.py check      # canary: rebuild digests, re-score baselines
python scripts/obst_bench.py selftest   # metric arithmetic on fixtures
python scripts/data_index.py            # regenerates the /data page catalog row
```

- **Human-gated validation.** The gold sample
  (`scripts/obs_t_gold.py --make` / `--score`) is human-gated and must not be
  regenerated unattended; `data/pwg_scan_index_tracker/ls_counts/pwg_ls_counts_2024-09-11.tsv`
  is dated evidence and is never regenerated (see `AGENTS.md`).
